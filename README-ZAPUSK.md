# Сеть магазинов «Браво» — как запустить на своём компьютере

Твой **четвёртый** учебный проект: игра-симулятор «управляем коммерческой
организацией» на Next.js + React. Ты — владелец сети продуктовых магазинов
«Браво». Две реалистичные фишки по сравнению с министерством:

1. **Рациональный найм.** Работодатель смотрит сначала на компетентность
   и опыт, и лишь потом на психологические особенности. Итоговый рейтинг
   кандидата = **65% профпригодность** (сфера, стаж, образование) **+ 35%
   соответствие типа должности** (модель А). У кандидатов — настоящее досье:
   профессия, образование, достижение из резюме и зарплатные ожидания.
2. **Рынок труда неполный.** Из всей палитры соционики доступны только
   8–12 случайных типов. Приходится набирать из того, что есть: где-то
   соглашаться на компромисс, где-то оставлять кресло пустым.

Бонус-механика: **ФОТ и бюджет**. Профессионалы стоят дороже — бюджет фонда
оплаты труда 800 тыс. грн/мес на 8 руководителей. Набрали одних звёзд? Владелец
заметит перерасход и урежет оценку.

## Зарплаты — по реальному рынку Украины

Цифры не выдуманы, а привязаны к украинскому рынку труда (медианы вакансий
Work.ua, октябрь 2025; средняя зарплата по Украине — 23 460 грн по Держстату):

- **медианный кандидат** стоит ≈ 78 тыс. грн — ровно медиана коммерческого
  директора по Work.ua;
- **финансовый директор ≈ 88 тыс. грн** (по Work.ua — 85 тыс.), **IT-директор
  ≈ 90 тыс.** — IT и финансы на рынке дороже всего;
- **«звёзды» (проф 90+, стаж 20) уходят в вилку 110–145 тыс. грн** — так платят
  топ-менеджменту (по обзорам — 120–300 тыс. в крупных сетях, нам до «крупных»
  ещё расти);
- **слабые кандидаты из чужой сферы — 30–45 тыс. грн** — уровень директора
  одного магазина (по Work.ua — 32,5 тыс.);
- надбавки за сферу (`FIELD_PREMIUM`): IT ×1.15, финансы ×1.12, закупки ×1.06,
  логистика/розница ×1.04, маркетинг ×1.03, HR ×1.0, качество ×0.9.

## Что нужно заранее

**Node.js версии 20 или новее.** Проверь в терминале:

```powershell
node -v
```

Если нет или версия старая — скачай LTS с https://nodejs.org и установи.

## Запуск за 4 шага

1. **Распакуй архив** в папку `Documents` (правый клик → «Извлечь всё...»).
   «Браво» — отдельный проект и соседям не мешает: если сапёр уже работает
   на `localhost:3000`, а тренажёр на `localhost:3001`, «Браво» откроется
   на `localhost:3002` (адрес появится в консоли).
2. **Открой терминал в папке** `bravo`: Проводник → клик в адресную строку →
   напиши `powershell` → Enter.
3. **Установи библиотеки** (один раз):
   ```powershell
   npm install
   ```
4. **Запусти игру:**
   ```powershell
   npm run dev
   ```
   Открой в браузере адрес из консоли (обычно **http://localhost:3000**) —
   и вперёд, в ритейл!

Остановить сервер: **Ctrl+C**. При следующем запуске: зайти в папку → `npm run dev` (install больше не нужен).

## Как играть

1. **Рынок труда** — выбери ситуацию: «Кадровое изобилие» (12 кандидатов),
   «Обычный рынок» (10) или «Кадровый голод» (8). Рынок покажет, кто
   искать пришёл и — главное — **кого на рынке сейчас нет**. Раз в игру
   доступен «Хедхантер»: заменит двух кандидатов новыми типами.
2. **Собеседования** — распредели кандидатов по 8 должностям сети:
   коммерческий, финансы, логистика, розница, HR, маркетинг, качество,
   IT. Кандидаты в списке сгруппированы **по профессиональным сферам**, а не
   по квадрам — как в настоящем HR-отделе. У каждой должности — итоговый
   рейтинг нанятого: «итог 82% · проф 90% · соционика 68%». Вверху — ФОТ
   команды против бюджета. На «скамейке запасных» видно, кому какой пост
   подошёл бы лучше.
3. **Штаб сети** — сверху ФОТ, дальше карта отношений между менеджерами
   (SVG-граф): зелёные линии комфортные, жёлтые нейтральные, красные
   пунктиром напряжённые. Кликни по линии — узнаешь, что за отношения.
   Потом 8 бизнес-кризисов: сорванная поставка молока, конкурент напротив,
   внеплановая проверка, увольнение кассиров, скачок цен, упавшие кассы,
   разгромный обзор блогера и решение «открывать ли пятый магазин».
   Вклад менеджера в кризис = 60% сила функции + 40% профессионализм.
4. **Итоговый отчёт** — ранг S–D и ЧЕТЫРЕ шкалы: кризисы, профессиональный
   уровень команды, итог назначений (проф + соционика), сплочённость.
   Отдельно видны две оси найма: можно собрать «профессионалов, которые
   не сходятся характерами» — отчёт это покажет. Плюс кадровый контекст
   (кого не было на рынке) и ФОТ против бюджета.

Прогресс сохраняется в браузере (localStorage): закрыл игру — продолжишь
с того же места. «Новый рынок» начинает всё заново.

## Структура проекта

```
bravo/
├── package.json            ← библиотеки и команды (те же 3 зависимости)
├── next.config.ts          ← настройки Next.js
└── src/
    ├── app/
    │   ├── page.tsx        ← ИНТЕРФЕЙС: рынок → найм → штаб → отчёт
    │   ├── layout.tsx      ← оболочка страницы
    │   └── globals.css     ← стили
    └── lib/
        ├── socionics-data.ts   ← переиспользовано из тренажёра (16 типов)
        ├── socionics-quiz.ts   ← переиспользовано (модель А, базовая/творческая)
        ├── relations.ts        ← движок 14 отношений (общий для всех игр)
        └── bravo.ts            ← НОВОЕ: должности, кризисы, кадровый рынок
```

## Проверка фактологии

Автотест на ~6700 проверок лежит в `scripts/test-bravo.ts`. Если у тебя
установлен bun, можно запустить:

```powershell
bun scripts/test-bravo.ts
```

Без bun — не страшно: тест уже прогнан, а код проверяется `npm run lint`.

Рядом лежит `scripts/calibrate-uah.ts` — калибровочный скрипт, которым я
подбирал бюджет ФОТ: он гоняет 400 рынков и показывает, сколько платит
автоподбор против бюджета. Запуск тот же: `bun scripts/calibrate-uah.ts`.

## Что тут интересного для обучения

- **Две оси найма**: `profFit` (сфера, стаж, образование) и `postFit`
  (функции типа по модели А) считаются раздельно и смешиваются с весами
  65/35 (`overallFit`). В отчёте обе оси видны по отдельности — так в коде
  показывают, что компетентность и совместимость — разные вещи.
- **Ограниченный ресурс**: генератор рынка (`generateMarket`) случайно
  выбирает подмножество типов — и вся игра строится вокруг нехватки.
  Так в коде моделируют реальность: «идеальных вариантов нет, решай».
- **Бюджет как ограничение**: `salaryFor` привязывает зарплату к
  профпригодности, а `payroll`/`PAYROLL_BUDGET` наказывают за команду
  из одних звёзд — тоже реалистичный приём моделирования.
- **Три слоя логики**: `relations.ts` (отношения) → `bravo.ts` (правила
  игры) → `page.tsx` (интерфейс). Движок отношений вынесен в общую
  библиотеку — его можно переиспользовать в следующей игре.
- **Чистые функции**: `simulateCrisis`, `autoAssemble`, `rerollBench` —
  на вход данные, на выход результат. Никаких обращений к интерфейсу —
  легко тестировать.
- **localStorage как база**: сохраняется вся партия (рынок, найм, фаза),
  а не только рекорд — третий пример работы с хранилищем браузера.
  Старые сохранения, начатые до введения найма по компетенциям,
  дозаполняет `normalizeCandidate`.
- **Переименование бренда без потери данных**: сеть называлась «Чудо»,
  но по рекламным соображениям её переименовали в «Браво». Прогресс жил
  в localStorage под ключом `chudo-game` — а при смене бренда партия
  должна выжить! Поэтому игра при старте проверяет старый ключ
  (`LEGACY_GAME_KEY`), переносит рекорд под новый `bravo-best` и
  зачищает старые записи. Это реальный приём миграции хранилища:
  ключи меняются, данные пользователей сохраняются.
- **Смена валюты без поломки сейвов**: при переходе с рублей на гривну
  у кандидатов появилось поле `cur: 'uah'`. Кандидаты из старых
  «рублёвых» сохранений это поле не имеют — и их зарплаты пересчитываются
  по гривневой шкале (`normalizeCandidate`). Маркер версии в данных —
  стандартный способ понять, по каким правилам записана старая строка.

Удачной игры — попробуй собрать команду одних профессионалов и посмотри,
что скажет отчёт про сплочённость 😉
